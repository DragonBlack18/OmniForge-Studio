# OmniForge Studio v0.1.4 — catálogo local de projetos

## Contrato funcional

- A interface **Meus projetos** permite cadastrar até 100 diretórios reais em um catálogo independente, no `app.getPath('userData')/project-catalog/projects.json`.
- O cadastro é uma inspeção somente-leitura de manifestos selecionados (Node/Electron, Python, Go, Rust, Java), com limite de 64 KiB. Nenhum processo de terceiros é executado.
- `Abrir` seleciona o projeto e carrega seu fluxo e seu explorador. O histórico e os arquivos de automação continuam dentro da pasta específica de cada projeto.
- `Esquecer` **não remove** pastas nem arquivos originais. Projetos offline permanecem cadastrados e aparecem como indisponíveis.
- Identificação por UUID, gravação privada atômica, verificações de symlink, tamanho de 256 KiB e contrato versionado. O catálogo não é sincronizado com nuvem.
- Trocas de projetos com alterações não salvas exigem confirmação e operações simultâneas de execução/gravação são bloqueadas na camada principal do Electron.

## Limitações honestas

- Não há descoberta automática de repositórios externos, extensão VS Code, Git commit, execução de comandos ou sincronização multi-dispositivo.
- A segurança de diretórios controlados por outro processo malicioso ainda depende de permissões do sistema operacional. Não utilizar em pastas não confiáveis com escrita concorrente hostil.
- A detecção do tipo de projeto é heurística de manifestos, não prova da linguagem usada em todos os arquivos.

## Gates

`npm test` cobre cadastro, duplicação, offline, persistência, symlinks, catálogo malformado, IDs e preservação dos arquivos. O `smoke:electron` no Windows abre e reabre um projeto através do catálogo, lê arquivos e verifica histórico persistente.
