# OmniForge Studio v0.1.2 — primeiro conector HTTP funcional

**Status:** implementado em branch, sujeito aos gates Windows/CI e revisão antes do merge.

## O que faz

Novo nó `http.localJson`, com entrada e saída JSON, suporta GET e POST para aplicações que oferecem HTTP em `127.0.0.1` (loopback) na mesma máquina. Com isso, um projeto Python, Java, Go ou Node.js que exponha uma API local pode ser chamado pelo grafo do OmniForge sem modificar o código daquele projeto.

Um fluxo real pode ser **Início manual → HTTP local JSON → Selecionar campo → Gravar JSON**. No POST, o corpo JSON enviado vem da saída do nó anterior; o resultado do HTTP é um JSON `{ "status": 200, "data": ... }`. Portanto, o nó Selecionar campo pode usar `data.valor`.

## Segurança e limitações técnicas

- Endereço limitado **estritamente** ao literal `http://127.0.0.1`, com porta TCP opcional. Sem DNS, IP externo, HTTPS remoto, credenciais na URL, fragmentos ou redirects.
- Métodos permitidos: GET e POST. Timeout por chamada de 100 a 10.000 ms.
- Requisições limitadas a 128 kB de JSON; respostas limitadas a 512 kB e a `application/json`.
- Solicita autorização explícita na janela Electron **antes de enviar qualquer requisição real**. Não memoriza permissão entre execuções.
- Simulação **não conecta à API** nem fabrica respostas. Nó HTTP e dependentes recebem `SKIP`; o resultado marca `partialSimulation=true`.
- Respostas HTTP fora de 2xx e erros interrompem o fluxo; não ocorrem gravações em estágios posteriores.
- O conector **não é** um ambiente de sandbox para serviços locais: uma API em `127.0.0.1` pode executar operações irreversíveis. Inspecione a URL e o método antes de autorizar.
- Ausentes nesta versão: autenticação, gerenciamento de segredos, DNS remoto, TLS, streaming, retry, webhook server, agendamento, idempotência de POST, transações entre projetos, API industrial e atualização automática.

## Testes

A suíte `tests/http.test.mjs` usa servidores HTTP reais efêmeros no loopback para verificar execução, simulação, aprovação, POST, GET, status, content-type, limite de tamanho, timeout, bloqueio de redirect e URLs externas.

## Como testar

1. Inicialize um serviço HTTP local que responda JSON, por exemplo um endpoint POST em `127.0.0.1:8000`.
2. Abra um workspace no OmniForge e adicione `HTTP local JSON` entre o gatilho e o seletor.
3. Configure URL, método e tempo limite. Conecte as portas.
4. Use **Validar**, depois **Simular** (sem chamadas reais).
5. Use **Executar**; leia cuidadosamente os destinos na confirmação e autorize somente se reconhecer o serviço.
6. Consulte o diagnóstico e o JSON produzido dentro de `.omniforge/output/`.
